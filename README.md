# 结构化输出 · Structured Output

让 DeepSeek Harness 的回答**先能被读懂，再谈信息量**。简单问题直接答；复杂任务先给结论，再按需要展开依据、步骤和风险；用户指定的格式与详略优先。

## 出发点

模型的输出经常有两个毛病：该一句话说完的非要说三段，该分层的却糊成一大段。读的人得自己从里面找重点、拼结构，注意力先被耗掉了。

这个插件想解决的就是这件事——**不是让回答更长或更"专业"，而是降低理解成本**：

- 该短就短，不强行列点、加标题、写总结；
- 该分层就分层：结论在前，依据在后，风险和下一步在相关处出现；
- 术语第一次出现时补一句白话，不假设读者是同行；
- 省掉重复套话，但不省略必要的不确定性、限制和风险。

约束只作用于**给人看的自然语言**。工具调用、代码、文件正文、程序读取的机器可读输出都各按自己的任务要求走，不会被这套表达偏好改写。

## 怎么实现

三层，各管一件事：

| 层 | 做什么 | 在哪 |
| --- | --- | --- |
| 系统提示词 | 5 条表达约定，常驻注入，优先级低于上层指令和用户要求 | `index.js` 的 `CONTRACT` |
| 运行时脚本 | 只在用户**句首**明确要求 JSON、表格或详细解释时，当轮追加一条对应的格式提醒 | `index.js` 的 `classify` / `apply` |
| 示例 | 中英正反例，用来校准"什么算明确要求"，以及措辞会不会过度约束 | `tests/` |

**系统提示词**是一段稳定的短文本：遵循用户指定的格式与篇幅、正确性和任务完成优先于简短、简单问题 1~3 句、复杂任务先结论后依据、术语补白话。它不描述具体任务，只定义"怎么说话"。

**脚本**只做一件事：在消息进入当前轮时判断句首是不是一个明确的格式指令，例如「只返回 JSON，字段为 …」「用表格对比这两个方案」「详细解释这两者的区别」，命中就给这一轮追加一句更具体的提醒；轮次结束、会话空闲或换会话时立刻清除。它**纯内存运行**：不保存消息正文、不发网络请求、不追加模型调用、不改动对话历史。

**示例**是这套规则的地基。提示词写宽了会把正常回答压短，写窄了又不起作用，所以用一组中英正反例去卡边界——句首明确要求 vs. 句中顺带提到、引用或代码块里出现的同一句话。这些用例随仓库以测试形式提供，运行时不会加载。

## 开启之后

- 回答更有条理：结论、依据、风险各在其位，不用读者自己重组。
- 注意力消耗更低：短问题不再被灌成长篇，长任务也不会缺关键步骤。
- 理解成本更低：术语有白话兜底，限制和不确定性不会被"看起来很有把握"的语气盖掉。
- 不牺牲正确性：宁可多写必要的一句，也不会为了简短省略验证结果、可运行代码或待解决的问题。

## 安装

首发版本适用于已验证的 **DeepSeek Harness 0.2.2-rc.5**。

在 DeepSeek Harness 的插件管理中选择通过 npm 安装，输入 `dsh-structured-output`。也可以使用命令行：

```sh
dsh plugin --profile desktop add dsh-structured-output
```

桌面版使用 `desktop`，独立 Web 配置可将其替换为 `web`。如果已启用旧的本地版 `@local/dsh-structured-output`，请先停用它，再安装公开版。安装后可在插件管理中停用、重新启用或卸载「结构化输出」。

## 怎么用

平时照常提问即可。需要特定格式时，把要求放在**句首**，例如「只返回 JSON。字段为 `total` 和 `average`」「用表格对比这两个方案」「详细解释这两者的区别」。插件会为这些明确的句首写法追加提醒。

这是有意的取舍：句尾补一句「只给 JSON」、行文中间提到格式、引用或代码块里出现的同样文字，都交给模型自己判断，不自动改写。宁可少触发，也不误改用户的意图。

模型仍会读完整条消息，JSON 结果需要由调用方按需校验。

## 开发

从 GitHub 克隆源码后运行 `npm test`。测试覆盖提示规则注册、格式触发、会话隔离和停用清理。仓库还提供 `tests/host-check.mjs`，可在 Electron 的 Node 模式下，用 `DSH_APP_ASAR` 指向已安装的 `app.asar` 来检查真实宿主的提示词服务：

```sh
npm test
DSH_APP_ASAR="/path/to/app.asar" node tests/host-check.mjs
```
